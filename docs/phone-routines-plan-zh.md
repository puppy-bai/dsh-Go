# 手机操控 1.0.16：任务与实施方案

本轮从社区版 1.0.15 继续，原始完整包和主工作树保留。目标是减少模型往返、避免旧屏幕编号误用，让操作按页面状态推进。这里的“像人”指先找目标、等待变化、确认结果；不添加用于规避平台检测的随机行为。

## 本轮交付与验收

1. 修复连续滚动和等待：每次采用新的屏幕号；已找到目标不再滚；到头和等待超时明确返回失败；等待期间只轮询文字，最后按需截图。用 fake driver 回归测试证明。
2. 新增 `run` 多步执行：单应用、1–60 步、240 秒执行预算；按文字重新定位，每步读新屏幕；预检 `dryRun` 不触碰设备；返回步骤 trace、已完成数及下一步。复用普通操作和安全门，不缓存无障碍节点，不自动重试点击/发送。
3. 支持 `tap`、`type`、`scroll`、`wait`、`assert`、`snapshot`、`key(back)`；目标消失、歧义、切到别的应用或用户停止时退出。普通操作批量确认，敏感动作和提交保留单独确认；每个动作仍走驱动的指纹校验。
4. 用本地 HTML 测试场覆盖填表、聊天草稿与模拟发送、异步等待、长列表与练习题。增加 24 项以上场景推演、任务技能包和安装说明。
5. 单元测试和静态检查通过后打 arm64 APK，校验版本、签名和散列，再通过 USB 覆盖安装并在真机测试。安装失败不自动卸载，保留设备数据。

## `run` 最小契约

```json
{
  "app": "com.android.chrome",
  "dryRun": false,
  "startAt": 1,
  "steps": [
    {"op":"assert", "text":"手机操控测试场"},
    {"op":"type", "target":"姓名", "text":"测试用户"},
    {"op":"tap", "target":"保存表单", "expect":"保存成功"}
  ]
}
```

`startAt` 和 `nextStep` 从 1 开始；恢复前必须观察实际页面，并在恢复步骤用 `requireText` 指定可见前提。`target` 是可见文字、提示或 viewId 片段，不是跨页面缓存的元素编号。`expect` 是动作后最多等 5 秒的可见结果。步骤参数在执行前整批检查；执行中断返回的 trace 不包含填写正文。无法确定动作是否生效时不重放，先读屏。

`wait` 使用 `ms`（0–10000）或 `text` + `timeoutMs`（250–10000），二选一。`scroll` 使用 `direction`，可带 `until/max`。不支持宏内坐标动作、无限循环、跨应用自动跳转；现有 `gesture/input` 继续用于模型确认后的坐标操作。重启后不自动续跑。

## 场景判断与后续顺序

- 视频：有界浏览和切换能用现有手势；需要模型看懂内容，长时间观看/音频理解和可靠播放完成事件仍需专门适配。
- 消息：先核对聊天对象、起草、核对内容再发送。持续无人值守自动回复需要通知触发、联系人白名单、去重、冷却和撤回策略，本轮不将它标为已经实现。
- 签到：检查是否已签到；普通按钮可操作，验证码、广告与风控不保证。
- 作业与练习：读题、解题、填入和校验可分段完成；数学图片/画布、动态选项和大量翻页要逐页判断，正式提交单独确认，不承诺答案正确率。
- 下一轮用真机的失败记录决定优先级：输入焦点/剪贴板 → 页面定位 → 消息通知插件 → 恢复与数据保护。真实成功率和耗时必须实测后填写。

本方案中的功能以最终源码、测试报告和真机记录为准。随包旧文档声称的测试数字不作为本轮验证结果。
